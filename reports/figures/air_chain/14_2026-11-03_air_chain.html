AIR proposal v2: explicit correspondence chain + Laplace mixture vs the pooled flow proposal¶

Issue #21. Spec: docs/a2b_air_proposal_v2_2026-11-03.md (Tim, 2026-11-03), incl. its Refinement section (Gauss–Newton builds q, no MCMC; forward–backward; C_a widened by σ_A). Branch exp/21-air-chain.

Description¶

Question. Pilot 3's proposal q(θ | A, B) (pooled encoder + spline flow, notebook 11) underfits: the gap KL(post ‖ q) grows with n_A (pilot-2 diagnostics: 0.28 / 0.94 / 1.08 nats at n_A = 1 / 5 / 10, J = 2). The proposal v2 claim: a proposal built from explicit per-point correspondence evidence has no pooled bottleneck and no branch averaging, so at equal K it should give higher ESS and a smaller NLL gap to the exact reference, increasingly so for larger n_A and wigglier g. If true, the d ≥ 2 work becomes learned message passing over location beliefs; if not, the bottleneck is elsewhere (decoder, or the transform prior itself).

Setup. Variant (c) of the spec, no learned parts (experimental/air/chain.py):

  1. B model: a GP on B (RBF, ML over a lengthscale × noise grid) → predictive mean/var on a G = 256 grid of u ∈ [0, 1].
  2. Evidence volumes C_a(u) = mean_s N(y_a; m_B(u), v_B(u) + s²) over 4 values s of σ_A's prior range (σ_A is latent; the fits use s = 0.02).
  3. Coherence: 1-D chain over A sorted by x; transitions p(u_{a+1} | u_a) estimated from S = 4096 prior draws of θ (KDE, bandwidth 0.02); forward filtering, backward sampling of M = 128 correspondence sets.
  4. Fit: per set, Levenberg–Marquardt for θ in whitened prior coordinates, first to the correspondences (τ = 0.03), then to the evidence objective; Laplace covariance (I + JᵀJ)⁻¹.
  5. Proposal: q = (1 − ε)·(1/M) Σ_m N(θ̂_m, Σ_m) + ε·prior, ε = 0.1 (the same defensive ε as pilot 3's flow).

Compared at equal K ∈ {8, 32, 128} importance samples, with pilot 3's decoder (σ-conditioned, Σ = 0) as the likelihood, on pilot 3's evaluation tasks (eval_tasks(J, 256, 777, ecdf), J ∈ {2, 16}, n_A ∈ {1, 2, 3, 5, 10}):

  • flow = (a): pilot 3's trained proposal of the same seed and J (with its ε-prior mixture);
  • flow_gn: the flow's M = 128 draws as seeds → Gauss–Newton + Laplace mixture (refinement §1: the flow proposes, GN sharpens);
  • chain_gp = (c);
  • chain_oracle = (c) with the true g as B model (an upper bound on what better emissions, variant (d), could give);
  • grid (J = 2 only): the exact dense-B Bayes reference on a 101² θ grid (pilot 3's G-ref). For J = 16 there is no exact reference: methods are compared with each other and with pilot 3's isref (K = 4096, same tasks, from snapshot results/air_rb/<pilot-3 eval>) by task id. Seeds 0, 1, 2 = pilot 3's checkpoint seeds (decoder and proposals of that seed); the tasks are the same for all seeds.

What to look for.

  • NLL(method, K) − NLL(grid) at J = 2 and NLL(flow) − NLL(chain_gp) at J = 2, 16, per n_A and K; paired by task.
  • ESS/K per proposal; logq_true (density of q at the true θ); rank_true (share of q draws with higher q density than θ_true; uniform if q is calibrated, piled at 1 if q misses θ_true); KL(post ‖ q) at J = 2 (64 tasks).
  • All of the above by the number of branches of g (monotone pieces), and the build cost per task.

Pre-registered criteria (paired mean over 256 tasks; a "cell" is (J, n_A); a criterion holds if it holds in each of the 3 seeds):

  • V2.0 sanity: at J = 2, n_A ≤ 3, chain_oracle NLL at K = 128 within 0.05 nats of pilot 3's isref (prior IS, K = 4096, the same decoder; joined by seed and task); chain_oracle KL(post ‖ q) ≤ chain_gp KL + 0.05 (better emissions do not hurt). Amended 2026-11-03, before the first pilot run: the original reference was grid, which uses the exact likelihood, so every proposal (also pilot 3's flow) sits ~0.15 nats above it because of the shared decoder (see Limits), and V2.0 could not pass whatever the proposal. isref has the same likelihood as the methods, so method − isref is the proposal's error alone. Noticed while preparing the analysis on the scratch probe tables; no pilot data had been produced. method − grid is still reported.
  • V2.1 primary: at K = 32, NLL(flow) − NLL(chain_gp) ≥ 0.05 nats in at least 2 of the 3 cells n_A ∈ {3, 5, 10}, for both J = 2 and J = 16.
  • V2.2: ESS/K(chain_gp) > ESS/K(flow) at K = 32 in the same cells.
  • V2.1b (reported, not gating): the same comparison for flow_gn vs flow (does GN + Laplace fix the flow's width?).
  • V2.3 n_A = 1: |NLL(flow) − NLL(chain_gp)| ≤ 0.05 (the spec expects (a) to stay competitive; reported, not gating).
  • V2.4 branches: the flow − chain_gp gap at n_A ≥ 3 increases with the branch count of g (reported, not gating).

GO / NO-GO. GO if V2.0, V2.1 and V2.2 hold: build the d ≥ 2 version (learned message passing over location beliefs) and the J-sampled prior. NO-GO if NLL(flow) − NLL(chain_gp) < 0.02 in every cell with n_A ≥ 2 at K = 32 (explicit correspondences buy nothing over the flow; the bottleneck is elsewhere). Otherwise INCONCLUSIVE. If V2.0 fails, the result is INCONCLUSIVE regardless (the chain construction itself is broken).

Limits.

  • 1-D, h = id, and J known (J = 2 or 16, fixed per run). The spec's setup samples J per task with a Laplace-evidence mixture over J; that needs a J-sampled training prior for decoder and flow. Staged next (isolation, not a scope cut).
  • Only (a) and (c) (plus the oracle-emission bound). (b) transport-token loop + flow and (d) learned emissions are staged after this (they need training); chain_oracle bounds what (d) can gain.
  • The likelihood is the trained decoder, not the exact one, so all methods share its error; at J = 2 grid uses the exact likelihood, so method − grid contains the decoder gap (~0.1–0.2 nats in pilot 2) in addition to the proposal gap. The comparison flow vs chain at equal K is unaffected.
  • The chain's transitions use a KDE over prior samples: fine in 1-D, no claim about d ≥ 2.
  • Pilot only (split 0 tasks, seed 777); nothing here is tuned on split 1.

def cell_mean(prop, K, J):
    x = NLL[(NLL.prop == prop) & (NLL.K == K) & (NLL.J == J)]
    return x.groupby(["seed", "n_a", "task"]).nll.mean()

def paired(a, b):
    """a − b per task, then mean per (seed, n_a); returns (seed-mean, seed-SE, task-SE) per n_a."""
    d = (a - b).dropna().rename("d").reset_index()
    ps = d.groupby(["seed", "n_a"]).d.mean().unstack("seed")
    tse = d.groupby("n_a").d.std() / np.sqrt(d.groupby("n_a").d.count())
    return pd.DataFrame({"mean": ps.mean(axis=1), "seed_se": ps.std(axis=1) / np.sqrt(ps.shape[1]) if ps.shape[1] > 1 else np.nan,
                         "task_se": tse, "min_over_seeds": ps.min(axis=1), "max_over_seeds": ps.max(axis=1)})

Interpretation¶

Three seeds (sweeps pilot_20261104-001215, -004520, -011821; 2 DONE members each, none failed, started or missing), 256 tasks per (J, n_A), the decoders and flow proposals of AIR pilot 3. The flow rows reproduce pilot 3's qis at Σ = 0 on the same tasks: K = 128 within 0.002 nats for every seed; K = 32 within 0.005 for seeds 0 and 1 and −0.015 / +0.017 (J = 2 / 16) for seed 2, where the per-task MC spread at K = 32 is about 0.2 nats (SE ≈ 0.006).

Result: the explicit chain proposal is as good as the flow, not better. At K = 32 the gain NLL(flow) − NLL(chain_gp) lies in [−0.015, +0.020] nats in every cell (task SE ≈ 0.003–0.010); the pre-registered 0.05 is not reached anywhere.

Why nothing can win here: no headroom at K = 32. At J = 2 the flow at K = 32 is only 0.048 / 0.042 / 0.041 / 0.023 / 0.012 nats above the prior-IS reference (isref, same decoder) for n_A = 1 / 2 / 3 / 5 / 10, and at K = 128 it is within 0.001–0.014. Even a perfect proposal could gain at most ≈ 0.04 nats at n_A = 3 and ≈ 0.01 at n_A = 10, so V2.1's 0.05 threshold was unattainable in two of its three cells. This is a pre-registration flaw (the threshold was set without the K = 32 → isref headroom from notebook 11 in view), not a property of the chain. It matches notebook 11: the proposal costs 0.02–0.03 nats at K = 32, and the decoder gap is 0.11–0.16. The distance from isref to the exact grid reference (0.11–0.16 nats at J = 2) is the decoder, shared by all four proposals. Notebook 13 makes the same point for MTPFN: neither model's remaining distance to Bayes is the warp or proposal.

What the chain does fix: the posterior shape (pilot 3's P3.1). KL(post ‖ q) at J = 2 grows with n_A for the flow (0.30 → 1.01), but stays at 0.35 → 0.67 for chain_gp and 0.33 → 0.51 for chain_oracle. The explicit correspondence + Laplace route tracks the posterior as it sharpens; the pooled flow proposes too wide. It does not show in NLL because the defensive prior share and K = 32 IS already absorb the flow's excess width.

Failure analysis, as pre-registered:

  • GP emissions (chain_gp vs chain_oracle): the true g lowers KL by 0.02–0.16 (most at n_A = 10). NLL is unchanged (within ±0.03 at K = 32, ≤ 0.007 apart at K = 128). The GP on B is not the bottleneck.
  • Chain vs flow seeds (chain_gp vs flow_gn): practically identical in NLL, KL (0.35/0.49/0.56/0.74/0.67 vs 0.35/0.50/0.57/0.74/0.68), ESS/K and PIT. Once GN + Laplace runs, where the seeds come from does not matter; the refinement's §1 (flow seeds + GN) is the cheaper route to the same q.
  • Laplace width (KL by σ_A): for every GN-based proposal, KL is 2–4× larger for σ_A < 0.0125 (chain_gp ≈ 1.0 at n_A ≥ 3) than for σ_A > 0.02 (≈ 0.25). The fixed fit noise 0.02 is too wide when the true noise is small. The oracle shows the same pattern, so it is the fit noise, not the emissions. A σ_A-marginal (or profiled) fit would narrow q further, but per the headroom argument it would not move NLL at K ≥ 32.
  • SBC/PIT: the flow is the best-calibrated proposal (KS 0.02–0.13); the GN-based ones sit at 0.06–0.17. They are mode-concentrated, with a slight shape mismatch from the fixed-noise Laplace. That is harmless for IS, given the defensive mixture.
  • Cost: chain_gp builds in 0.10–0.49 s per task, flow_gn in 0.05–0.30 s; both grow with n_A at J = 16.

Proposed verdict: INCONCLUSIVE as registered, read as a practical NO-GO for the question. The rule outcome is INCONCLUSIVE only because one cell sits on the 0.02 NO-GO edge. Substantively there is nothing for a better proposal to win in d = 1 at K ≥ 32: proposal quality is no longer AIR's bottleneck; the decoder is. A second pilot of this question is not proposed. The chain stays in experimental/ as a reference for d ≥ 2, where the flow's excess width may cost more and the KL improvement may become NLL. Whether to test that is a scope decision for the d = 2 stage of AIR (pilot 3 rule 1), not a rerun here.
