# AIR proposal v2: explicit correspondence chain + Laplace mixture vs the pooled flow proposal

## Question

See the description at the top of `notebooks/14_2026-11-03_air_chain.ipynb`; not retyped here.

## §0 Design and refinement (2026-11-03)

**Idea** (Tim, proposal v2): pilot 3's flow proposal reads (A, B) through one pooled 256-number summary c, which
must discover the per-point evidence implicitly, averages over branches (softmax attention) and compresses n_A maps
into one vector. Replace it by explicit per-point correspondence evidence C_a(u), a coherence step through the
warp's smoothness, and a proposal built from the resulting correspondences; multimodal by construction, as sharp
as the data, with an exact density for IS.

**Refinement** (Tim, same day; recorded in the spec's *Refinement* section, it supersedes "MCMC moves" in step 4):
- Gauss–Newton is used to *build* q, never to move drawn samples (that would destroy q's density): seeds (chain
  correspondence sets, or flow draws) → a few GN steps to the mode → a Laplace Gaussian per mode;
  q = (1/M) Σ_m N(θ̂_m, (Λ + F_m)⁻¹). Seeds sharing a mode just weight it more. Flow seeds + GN + Laplace would fix
  the flow's tendency to propose too wide.
- Coherence in 1-D: exact forward–backward along A sorted by x (HMM over B locations; emissions C_a, monotone smooth
  transitions from the transform prior, T(0) = 0, T(1) = 1 as end states); backward sampling gives the seeds.
  In d ≥ 2: a kNN graph over A with beliefs over B locations and learned messages (a GNN doing approximate BP).
- C_a(u) = B's predictive density of y_a at u, widened by σ_A, on a G ≈ 256 grid, once per task. It ignores x_a
  (the prior enters through the chain) and needs h (ranks, candidate h or a learned emission if h ≠ id).

**Implementation** (`experimental/air/chain.py`; differences from the text): LM (damped GN) with a
finite-difference Jacobian; transitions are the exact pairwise prior marginals of (T(x_a), T(x_{a+1})) from 4096
prior draws rather than a stretch kernel; σ_A is latent, so the widening is a mixture over its prior range; a
defensive ε = 0.1 prior share stays in q (as in pilot 3). Proposals compared: `flow` (a), `flow_gn` (flow seeds +
GN + Laplace, refinement §1), `chain_gp` (c), `chain_oracle` (c with the true g; bounds learned emissions (d)).
Criteria V2.0–V2.4 are pre-registered in notebook 14; `flow_gn` was added before the first run (V2.1b, reported).

**Scratch probes** (CPU, 16 tasks, seed-0 checkpoints, J = 2 only; `uv run` scratch, not reportable, no snapshot):
at J = 2 the four proposals were within a few hundredths of a nat of each other at K = 32 for all n_A, with
ESS/K 0.5–0.85 for all of them, and all about 0.13–0.2 nats above the exact grid reference. If this holds on 256
tasks, J = 2 does not separate proposals (the gap to the grid is the shared decoder) and the question is decided
at J = 16. KL(post ‖ q) also grows with n_A for `chain_oracle`, which has the true g, so part of it is plausibly
the fixed fit noise (0.02) being wider than small true σ_A; to check in the pilot by σ_A.

**Amendment before the first pilot run (2026-11-03, evening).** V2.0's reference changed from `grid` (exact likelihood)
to pilot 3's `isref` (prior IS, K = 4096, same decoder): against `grid` every proposal carries the shared ~0.15-nat
decoder gap, so V2.0 could not pass and would have made the experiment INCONCLUSIVE regardless of the proposal.
No pilot data existed; V2.1–V2.4 and the GO/NO-GO are unchanged.

## §1 Pilot (2026-11-03)

**What ran.** `experiment=air_chain` (mode `chain_eval`, code 7a57029) on ulysses, one sweep per seed with the
pilot-3 decoder (`air_rb/pilot_20261103-101808/<seed>`) and proposals (J = 2: `-120248`, J = 16: `-134243`):
`results/air_chain/pilot_20261104-001215` (seed 0), `-004520` (seed 1), `-011821` (seed 2). Each has 2 members
(J = 2, 16); all 6 are DONE, none failed, started or missing. Each seed took about 33 min (J = 2: 12.5 min,
J = 16: 20.5 min) on one GPU. 256 tasks per (J, n_A), M = 128. The V2.0 reference is
`results/air_chain/pilot3_isref.parquet`: pilot 3's `isref` rows from `air_rb/pilot_20261103-184131` / `-211850` /
`-160447` (seeds 0 / 1 / 2). Consistency check: the `flow` rows reproduce pilot 3's `qis` at Σ = 0 on the same tasks
(K = 128 within 0.002 nats; K = 32 within 0.005 for seeds 0 and 1, −0.015 / +0.017 for seed 2, IS noise with a
per-task SD of about 0.2).

**Result** (notebook 14; mean over 3 seeds; Δ = NLL(flow) − NLL(chain_gp), nats per query):
- V2.0 pass. chain_oracle at K = 128 is 0.019 / 0.010 / 0.009 nats above isref at n_A = 1 / 2 / 3 (J = 2). Its KL
  is at most chain_gp's.
- V2.1 fail. Δ at K = 32 lies in [−0.015, +0.020] in every cell; 0 of 3 cells reach 0.05 at either J. V2.1b
  (flow_gn) is in [−0.023, +0.014].
- V2.2 fail. The chain's ESS/K is higher only at J = 2 with n_A = 5 and 10 (0.67 vs 0.63; 0.62 vs 0.55), and at
  J = 16 with n_A = 10 (0.35 vs 0.33).
- V2.3 holds: −0.008 at J = 2 and −0.010 at J = 16.
- V2.4: no trend with the number of branches.
- NO-GO condition (Δ < 0.02 in every cell with n_A ≥ 2): not met, by one cell. At J = 16 with n_A = 2, Δ = +0.020.
- **Rule outcome: INCONCLUSIVE.**

**Interpretation.**
- *The cause is headroom.* At J = 2 the flow at K = 32 is only 0.048 / 0.042 / 0.041 / 0.023 / 0.012 nats above
  isref (n_A = 1 / 2 / 3 / 5 / 10), and at K = 128 it is within 0.014. So V2.1's 0.05 was unattainable at
  n_A = 5 and 10 even for a perfect proposal. This is a pre-registration flaw: the threshold was set without
  notebook 11's K-to-isref gap in view.
- *The chain improves the shape of q.* At J = 2 the mean KL(post ‖ q) at n_A = 10 is 0.67 for chain_gp, 0.51
  for chain_oracle and 1.01 for the flow, which addresses pilot 3's P3.1 failure. It does not reach the NLL.
- *Neither the emissions nor the seeds matter.* chain_gp ≈ flow_gn in NLL, KL and ESS. Once GN + Laplace runs, the
  seed source is irrelevant, and the GP emissions cost KL but no NLL.
- *The fit noise is too wide for small σ_A.* KL is 2–4× larger for σ_A < 0.0125 than for σ_A > 0.02, for the
  oracle too, so the fixed fit noise (0.02) is the cause.
- *The decoder is the binding gap.* isref − grid is 0.11–0.16 nats, as in notebooks 11 and 13.

**Proposed verdict: INCONCLUSIVE as registered; in substance a NO-GO for d = 1.** Proposal quality is no longer
AIR's bottleneck at K ≥ 32. No second pilot is proposed. Whether to revisit the chain or BP in d ≥ 2, where the
flow's excess width may cost NLL, belongs to AIR's d = 2 stage. Not decided (the user runs `decide`).
